SM-T515 BPF backport notes
=========================

Source and scope
----------------

The ``bpf_5.4`` branch starts from ``perm-ksun`` at ``029f8de0a3dc``
(Linux 4.4.177). Its existing BPF stack closely matches donor checkpoint
``612e1a2f5261`` from Andeveloperlab/exynos-8895, branch ``sep-16.1``.

The cumulative integration includes 980 selected BPF/prerequisite commits,
ending at ``6d53893e0e29`` plus fixes ``1905bd6b2166`` and ``8b2c7ac83908``.
See ``t515-backport-sources.txt`` for the full source list. Unrelated device
imports, EROFS, Incremental FS, cgroup-v2 modernization, and the broad vmalloc
allocator replacement are excluded.

This is a set of 5.4-era BPF backports onto Linux 4.4, not a complete Linux
5.4 BPF implementation. In particular, the donor defines JMP32 in the UAPI
without implementing execution, and its SK_REUSEPORT attach path is incomplete.
Programs must use features supported by this backport and the target config.

Integration decisions
---------------------

* Preserve target T515 drivers, configuration, UDP/reuseport RCU fixes,
  SELinux BPF hooks, no-AUDIT compatibility, and existing ReSukiSU manual hooks.
* Supply the memory-allocation and memory-attribute APIs needed by BTF and the
  verifier using existing 4.4 implementations, with allocation overflow checks.
* Preserve F2FS's existing private allocation/fault-injection behavior.
* Retain target thin archives, linker section garbage collection, WireGuard,
  and Samsung FMP build handling.
* Correct ARM64 JIT second-pass code-size initialization and BPF map security
  cleanup. Preserve the target XDP event-output copy fix.
* Adapt tracing, socket references, and network helper APIs to the target.
  Correct cloned BPF socket-storage ownership and locked socket-send paths.
* Reject negative BPF getsockopt lengths before copying buffers.
* Add bpffs ``renameat2(RENAME_NOREPLACE)`` support required by Android T+
  BPF loaders when moving temporary pins into SELinux-labelled directories.
* Preserve the disabled remote-controller configuration under its new Kconfig
  name, and leave the optional TLS module disabled. Stream parser remains
  built in for sockmap support.

Android compatibility
---------------------

The donor's root-only uname compatibility commits are included separately at
the user's request. ``bpfloader``, ``netbpfload``, and ``netd`` process-name
prefixes running as UID 0 see release ``5.4.3020``. Other callers see the real
kernel release. This shim does not add any BPF capability itself.

Building and validation
-----------------------

Run the existing script::

    ./build_kernel.sh

It uses ``/home/msstore/Desktop/toolchain/bin/aarch64-linux-android-`` by
default, the ``exynos7885-gta3xl_defconfig`` target, Android platform 11, and
available CPU parallelism. ``CROSS_COMPILE`` and ``JOBS`` may be overridden.
The script stops on configuration or build failure. The host dtc lexer fix
allows building with modern host GCC.

The primary artifacts are ``arch/arm64/boot/Image`` and ``Image.gz``. Device
trees are generated by the default build as before. A successful cross-build
checks compilation/linking; it does not establish boot or runtime correctness
on SM-T515 hardware. On-device validation should cover Android BPF loader
startup, connectivity, cgroup programs, maps, and the ARM64 JIT.

Existing KernelSU limitation
---------------------------

The starting repository has a dangling ``drivers/kernelsu`` link and no
KernelSU Kconfig/Makefile wiring. Kconfig drops the requested ``CONFIG_KSU``
options. This branch preserves the existing manual hooks; it does not supply
the missing ReSukiSU source or reconnect its build.
